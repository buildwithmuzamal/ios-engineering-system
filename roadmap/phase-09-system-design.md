# Phase 09 — System Design

> **Purpose:** Learn to design software before writing code. This phase focuses on engineering decisions, trade-offs, scalability, and building systems that are easy to maintain and evolve.

---

# Goal

Develop the ability to transform requirements into well-designed, maintainable software architectures.

---

# Learning Outcomes

By the end of this phase you should be able to:

- Design applications before implementation.
- Model business domains.
- Evaluate architectural trade-offs.
- Design scalable features.
- Communicate design decisions clearly.
- Review and improve existing architectures.

---

# Module 1 — System Design Fundamentals

## Core Topics

- What is System Design?
- Requirements Gathering
- Functional vs Non-functional Requirements
- Constraints
- Trade-offs

---

## Learning Objectives

After completing this module you should be able to:

- Answer clearly: What is System Design?
- Understand Requirements Gathering and recognize when it is the right tool.
- Understand Functional vs Non-functional Requirements and recognize when it is the right tool.
- Understand Constraints and recognize when it is the right tool.
- Understand Trade-offs and recognize when it is the right tool.
- Apply the module concepts in the mini project without copying a full solution.
- Use official documentation as the primary reference for this module.

---

## Parallel Learning Layers

### Git

- Version architecture decision records with Git.
- Keep design notes alongside code changes.
- Use branches for competing design experiments.

### Xcode

- Navigator
- Quick Help
- Breakpoints
- Documentation viewer

### Apple Documentation

- Official docs related to What is System Design?, Requirements Gathering, Functional vs Non-functional Requirements, Constraints

### WWDC

- Only sessions that directly strengthen this module

### Best Practices

- Prefer clarity when working with What is System Design?.
- Keep responsibilities small and names meaningful.
- Validate understanding with a working example before moving on.

### Design Thinking

- What problem does What is System Design? solve?
- What would a simpler alternative look like?
- What trade-offs appear if this is overused?

### Architecture Thinking

- Where does this concept belong in a production app?
- What should stay out of the UI layer?
- How would this decision affect testing and change later?

### Open Source

- Find a small open-source example related to What is System Design?

### AI

- Ask AI to explain What is System Design? after you attempt it yourself.
- Request a review of your design, not a full generated solution.
- Challenge AI suggestions against Apple documentation.

### English

- Write a short explanation of What is System Design? in your own words.
- Use precise terminology in notes and commit messages.
- Practice explaining trade-offs as you would in a pull request.

### Notes

- Document What is System Design?, Requirements Gathering, Functional vs Non-functional Requirements, Constraints.
- Capture common mistakes and Apple recommendations.
- Link related modules and future spiral topics.

### Reflection

- Can I teach What is System Design? to another engineer?
- What is still unclear?
- How does this connect to previous phases?

---

## Mini Project

- Build a small focused exercise that proves you understand What is System Design?.
- Keep the scope small enough to finish, but realistic enough to reuse later.
- Document one design decision and one mistake you corrected.

---

## Exit Criteria

You should be able to:

- Teach the idea behind: What is System Design.
- Use Requirements Gathering correctly in a realistic scenario and explain the trade-offs.
- Use Functional vs Non-functional Requirements correctly in a realistic scenario and explain the trade-offs.
- Use Constraints correctly in a realistic scenario and explain the trade-offs.
- Finish the mini project and describe one design decision you made.
- Write permanent notes covering the core topics, mistakes, and Apple guidance.
- Meet every Learning Objective for this module.
