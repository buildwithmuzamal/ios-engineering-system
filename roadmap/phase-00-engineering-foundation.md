# Phase 00 — Engineering Foundation

> **Purpose:** Build the engineering habits, workflow, and tools that will support every later phase.

---

# Goal

Before mastering Swift or SwiftUI, become comfortable with the daily workflow of a professional iOS engineer.

---

# Learning Outcomes

By the end of this phase you should be able to:

- Work confidently with Git basics.
- Navigate Xcode efficiently.
- Read Apple documentation.
- Debug simple problems.
- Keep structured engineering notes.
- Use AI to learn instead of copy.
- Follow a repeatable engineering workflow.

---

# Module 0.1 — Engineering Mindset

## Core Topics

- What is Software Engineering?
- Learning philosophy
- Problem solving
- Engineering workflow

---

## Learning Objectives

After completing this module you should be able to:

- Explain what software engineering is and how it differs from only writing features.
- Adopt a mastery-based learning philosophy for this repository.
- Solve problems by understanding before coding.
- Follow a repeatable daily engineering workflow.
- Apply the module concepts in the mini project without copying a full solution.
- Use official documentation as the primary reference for this module.

---

## Parallel Learning Layers

### Git

- Initialize and configure Git.
- Use status, add, commit, and log confidently.
- Write clear commit messages for foundation work.

### Xcode

- Navigator
- Quick Help
- Breakpoints
- Documentation viewer

### Apple Documentation

- Apple Developer documentation home and how professionals navigate it

### WWDC

- Only sessions that directly strengthen this module

### Best Practices

- Prefer clarity, consistency, and deliberate practice over rushing.
- Keep responsibilities small and names meaningful.
- Validate understanding with a working example before moving on.

### Design Thinking

- What problems does an engineering mindset solve that tutorials do not?
- What would a simpler alternative look like?
- What trade-offs appear if this is overused?

### Architecture Thinking

- How does workflow design affect long-term maintainability?
- What habits prevent accidental complexity later?
- How should learning systems be structured so knowledge compounds?

### Open Source

- Browse a mature open-source README and notice how engineering culture is communicated

### AI

- Ask AI to critique your engineering workflow notes after you write them yourself.
- Request a review of your design, not a full generated solution.
- Challenge AI suggestions against Apple documentation.

### English

- Write a short explanation of software engineering in your own words.
- Use precise terminology in notes and commit messages.
- Practice explaining trade-offs as you would in a pull request.

### Notes

- Document your learning philosophy, problem-solving approach, and engineering workflow.
- Capture common mistakes and Apple recommendations.
- Link related modules and future spiral topics.

### Reflection

- Can I teach my engineering workflow to another engineer?
- What is still unclear?
- How does this connect to previous phases?

---

## Mini Project

- Write your personal engineering workflow checklist for this repository.
- Keep the scope small enough to finish, but realistic enough to reuse later.
- Document one design decision and one mistake you corrected.

---

## Exit Criteria

You should be able to:

- Teach what software engineering means in your own words.
- Show your learning philosophy and workflow checklist.
- Finish the mini project and describe one design decision you made.
- Write permanent notes covering the core topics, mistakes, and Apple guidance.
- Meet every Learning Objective for this module.
