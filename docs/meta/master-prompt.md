# Curriculum Quality Gate

Before any module, lesson, project, roadmap update, or repository document is considered complete, evaluate it using the following quality gates.

---

## 1. Knowledge

Can the learner explain:

- What this concept is?
- Why it exists?
- Which problem it solves?
- When it should be used?
- When it should NOT be used?

If not, the lesson is incomplete.

---

## 2. Practical Skill

Can the learner successfully apply the concept?

Examples include:

- Writing code
- Refactoring code
- Debugging
- Building features
- Designing APIs
- Solving engineering problems

If the learner has not applied the concept, the lesson is incomplete.

---

## 3. Engineering Judgment

Can the learner evaluate trade-offs?

Examples:

- Why use a struct instead of a class?
- Why choose MVVM instead of MVC?
- Why use async/await instead of callbacks?
- Why introduce dependency injection?

Engineering education should build judgment, not only implementation skills.

---

## 4. Communication

Can the learner explain the concept clearly?

Examples include:

- Writing notes
- Technical discussions
- Pull Request descriptions
- Documentation
- Code Review comments

The ability to communicate technical ideas is part of engineering mastery.

---

## 5. Reflection

Can the learner answer:

- What did I learn?
- What mistakes did I make?
- What still confuses me?
- How does this connect to previous knowledge?

Reflection reinforces long-term understanding.

---

A lesson should satisfy all five quality gates before considering it complete.
