# Software Engineering Cheat Sheet

A simple reference for starting any software project.

---

# Software Engineering

## Definition

> **Software Engineering is the process of solving problems by designing, building, testing, releasing, and improving software using engineering principles.**

In simple words:

> **Software Engineering = Building software in a systematic and reliable way.**

---

# Software Developer

## Definition

> **A software developer is someone who solves problems by designing and building software using code, tools, and good decisions.**

Remember:

- Programming languages are tools.
- Coding is one skill.
- Problem solving and decision making are the real job.

---

# Learning Philosophy

## Definition

> **Learning Philosophy = Your approach to learning and improving.**

Good philosophy:

> **Learn → Understand → Practice → Build → Get Feedback → Improve**

Don't learn to memorize.

Learn to solve problems.

---

# Problem Solving

## Definition

> **Problem Solving = Understanding a problem, finding possible solutions, choosing the best one, and implementing it.**

Simple process:

```
Understand
    ↓
Analyze
    ↓
Find Solutions
    ↓
Choose Best Solution
    ↓
Implement
    ↓
Improve
```

---

# Engineering Workflow

## Definition

> **Engineering Workflow = The repeatable process of turning an idea into working software.**

Complete workflow:

```
Idea
   ↓
Planning
   ↓
Design
   ↓
Code
   ↓
Test
   ↓
Release
   ↓
Improve
        ↺
```

---

# Phase 1 — Idea

## Definition

> **Idea = Find a problem worth solving.**

### Goal

Understand the real problem.

### Questions

- What problem am I solving?
- Who has this problem?
- Why does this problem exist?
- Why is it important?
- Can software solve it?
- Is my idea actually solving the problem?

✅ If you can answer every question clearly, the Idea phase is complete.

---

# Phase 2 — Planning

## Definition

> **Planning = Decide what you're going to build before writing code.**

### Goal

Create a clear plan.

### Questions

## Problem

- What problem am I solving?

## Users

- Who am I building this for?

## Goal

- What does success look like?

## Scope

- What features are included?
- What features are NOT included?

## Constraints

- Time?
- Budget?
- Platform?
- Team size?

## Tasks

- What are the major tasks?

## Risks

- What could go wrong?

✅ If every question has an answer, Planning is complete.

---

# Phase 3 — Design

## Definition

> **Design = Decide how the software will work before writing code.**

### Goal

Create the blueprint.

### Questions

## Architecture

- Which architecture will I use?
- Why?

## Data

- What models do I need?
- How are they related?

## User Interface

- What screens exist?
- What does each screen do?

## Navigation

- How does the user move through the app?

## Data Flow

- How does data move through the app?

## APIs

- Which APIs or services are needed?

## Edge Cases

- What happens if something goes wrong?
- No internet?
- Empty data?
- Invalid input?

✅ If every question has an answer, Design is complete.

---

# Phase 4 — Code

## Definition

> **Code = Turn the design into working software.**

### Goal

Build the solution.

### Questions

- Am I following my design?
- Is the code readable?
- Is the code simple?
- Does every file have one responsibility?
- Am I avoiding unnecessary complexity?
- Does the feature actually work?

✅ If yes, Code phase is complete.

---

# Phase 5 — Test

## Definition

> **Test = Verify that the software behaves correctly.**

### Goal

Find problems before users do.

### Questions

- Does every feature work?
- What happens with invalid input?
- What happens with empty data?
- What happens without internet?
- Can the app crash?
- Did I test important user flows?
- Are existing features still working?

✅ If yes, Testing is complete.

---

# Phase 6 — Release

## Definition

> **Release = Deliver the software to users.**

### Goal

Ship the product.

### Questions

- Is every planned feature finished?
- Are critical bugs fixed?
- Is the release build ready?
- Have I verified the production build?
- Is the app ready for users?

✅ If yes, Release is complete.

---

# Phase 7 — Improve

## Definition

> **Improve = Learn from real users and make the software better.**

### Goal

Continue improving the product.

### Questions

- What feedback did users give?
- Which bugs should be fixed first?
- Which features provide the most value?
- What can be simplified?
- What should be removed?
- What should be added in the next version?

✅ Once priorities are decided, start again from the Planning phase.

---

# Golden Rules

## Rule 1

Don't start coding until you understand the problem.

---

## Rule 2

Solve the right problem before writing the right code.

---

## Rule 3

Keep Version 1 as small as possible.

---

## Rule 4

Simple software is easier to build, test, and maintain.

---

## Rule 5

Code is only one phase of software engineering.

---

## Rule 6

Every release teaches you something.

---

## Rule 7

Great software is built through many iterations, not one perfect version.

---

# Quick Checklist

```
☐ Idea
☐ Planning
☐ Design
☐ Code
☐ Test
☐ Release
☐ Improve
```

Whenever starting a new project, go through these phases one by one. Don't move to the next phase until you can confidently answer the questions for the current one.
